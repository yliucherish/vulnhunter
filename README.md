# VulnHunter — Web 漏洞扫描器

[![CI](https://github.com/yliucherish/vulnhunter/actions/workflows/ci.yml/badge.svg)](https://github.com/yliucherish/vulnhunter/actions/workflows/ci.yml)

> 一个自研的轻量级 Web 漏洞扫描器，覆盖 SQL 注入、XSS、命令注入、SSRF 等
> OWASP Top 10 常见漏洞的自动化检测。
>
> **本工具仅供授权环境下的安全测试与学习研究使用。**

## 核心亮点

- **异步爬虫引擎**：asyncio + aiohttp，自动识别表单与 URL 参数，同源限制与去重，内置副作用黑名单（**URL 与表单字段名双重判定**——改密/注销类表单根本不进注入点列表）
- **SQL 注入检测**：报错注入（多数据库错误特征库）+ 布尔盲注（归一化 + 双次稳定性校验）+ **Union 注入**（marker 上下文判别）+ **时间盲注**（双时长差值法）；布尔/时间探测均覆盖**字符型与数值型两种上下文**（应对 `escape_string` 类转义）
- **XSS 检测**：反射型 XSS，上下文感知（HTML 文本 / 标签属性 / JS 字符串分别构造 payload）
- **命令注入检测**：回显型（只认随机算术的执行结果）+ **多分隔符变形**（`;`/`&&`/`|`/换行/命令替换，应对黑名单）+ 时间盲注（逐分隔符尝试）
- **SSRF 检测**：带外触发（OAST），扫描器自带临时回调服务，无回显场景也能检出
- **登录态支持**：`--cookie` 注入会话，可扫描需认证的系统（如 DVWA 登录后页面）
- **慢端点串行通道**：单次请求超过阈值即把注入点标记为慢端点，后续请求转入容量 1 的串行通道——应对 PHP session 锁等"目标有状态性"导致的并发饥饿（DVWA 21s captcha 黑洞曾让整场扫描 60/100 任务超时，见 SPEC 踩坑记录⑥）
- **失败可见性**：请求失败显式分类（timeout/connection/other）并统计，超时按 `baseline×2 < 预算` 判别"排队竞争"（重试一次）与"固有慢"（不重试），报告如实呈现覆盖率与慢端点——**扫描器可以漏报，但不能假装扫过了**
- **报告系统**：扫描完成后生成 HTML 可视化报告，含漏洞详情、判定依据、修复建议与覆盖率统计
- **规则可扩展**：检测器插件化，新增漏洞类型只需实现 Detector 接口并注册

## 架构

```
cli.py → engine.py（并发调度，Semaphore 限流，统一注入登录 Cookie）
           │            · 检测器优先级调度（快检先行，不被慢请求饿死）
           │            · 慢端点标记 → 容量 1 串行通道（防会话锁饥饿）
           │            · 失败分类统计 + 连接类熔断 + 超时重试判别式
           │            · 报告如实呈现覆盖率/慢端点
           ├─ crawler.py（BFS，产出 InjectionPoint 列表，副作用黑名单：URL + 字段名）
           └─ detectors/（插件化）
                ├─ sqli.py   报错注入 + 布尔盲注 + Union 注入 + 时间盲注
                ├─ xss.py    反射型 XSS，上下文感知
                ├─ cmdi.py   命令注入（回显 + 变形 + 时间盲注）
                └─ ssrf.py   SSRF（带外触发）
           ├─ _timing.py    时间型盲注公共判别（双时长差值 + 换序复验）
           └─ _http.py      请求发送 + 反射检测 + FetchError 分类 + 慢端点测量
report.py（HTML 报告，含覆盖率与慢端点统计）
```

**测试**：`pytest tests/ -v`（15 个用例：检测器真阳性/真阴性对称设计 +
v0.3.2 调度回归——爬虫字段名过滤 / 慢端点标记 / 串行通道 / 重试判别式 / 端到端场景）

## 快速开始

```bash
pip install aiohttp beautifulsoup4

# 基础扫描（本地靶场，禁止对未授权目标使用）
python -m vulnhunter.cli http://127.0.0.1:8888 --depth 2 --report report.html

# 带登录态扫描（先用浏览器登录目标，从开发者工具复制 Cookie）
python -m vulnhunter.cli http://localhost/dvwa --depth 2 \
       --cookie "PHPSESSID=xxxx; security=low"
```

内置自测靶场：`python tests/vulnerable_app.py`（监听 127.0.0.1:8888），
包含 XSS / SQL 注入 / 命令注入 / SSRF / 需登录页面五类场景。

## 实测数据（DVWA v1.10，v0.3.2）

完整数据、源码级漏报归因与三次"0 检出"排查过程见 [tests/dvwa_results.md](tests/dvwa_results.md)。

两种测量方式分开呈现（分离"检测能力"与"并发环境"两个变量）：

### v0.3.2 复扫数据（Docker 恢复后，2026-10-23）

| 安全等级 | 爬取页面 | 注入点 | 全站扫描检出 | 检测完成度 | 请求失败 | 误报 |
|---|---|---|---|---|---|---|
| low | 38 | 25 | **8** | **100/100** | **0** | 0 |
| medium | 38 | 25 | **7** | **100/100** | **0** | 0 |
| high | 38 | 21 | **3** | 82/84 | 2（brute 超时） | 0 |

high 档的 2 次失败全部集中在 `brute` 端点（基线 45s/请求，超过 45s 超时上限），
非连接类失败；其余 82 项检测全部完成。

### v0.3.1 数据（旧，保留用于对比调度修复的效果）

| 安全等级 | 爬取页面 | 注入点 | 全站扫描检出* | 定向复测检出** | 误报 | 可利用场景命中（定向） |
|---|---|---|---|---|---|---|
| low | 26 | 28 | 6 | **7** | 0 | **6/6** |
| medium | 26 | 28 | 5 | **4*** | 0 | 4/6 |
| high | 26 | 25 | 1（captcha 黑洞事故） | **3** | 0 | **3/3** |

> **v0.3.2 的调度修复带来了什么**：
>
> | 安全等级 | v0.3.1 检出 | v0.3.2 检出 | 变化 |
> |---|---|---|---|
> | low | 6 | **8** | +2 |
> | medium | 5 | **7** | +2（含此前"待查"的 sqli_blind） |
> | high | 1（captcha 黑洞事故） | **3** | **+2**（含命令注入时间盲注） |
>
> 三档的"检测完成度"从"部分超时丢失战果"提升到 **low/medium 100/100、0 失败，
> high 82/84**。
>
> 两个此前存疑的点在复扫中都得到了解释：
> - **medium 的 sqli_blind 时间盲注成功检出**——它此前是被超时丢掉的战果，
>   不是检测能力问题；
> - **high 档检出了命令注入时间盲注**——high 档 `exec` 用黑名单删掉 `;&|`，
>   靠换行符 `\n` 形态的 payload 绕过成功，验证了 payload 变形策略的有效性。
>
> 这也反过来印证了 v0.3.2 的归因是对的：
> **丢检的根因是慢端点串行化导致的超时，而不是检测器写错了。**

\* 全站扫描：`--depth 3 --concurrency 4`，产品真实行为。
\*\* 定向复测：`tests/targeted_check.py`，每次全新登录会话、单点串行，受控实验。

> **每一处未检出都有源码级解释**：high 档 sqli/sqli_blind 的参数改由 session/cookie
> 提供（HTTP 层无攻击面）；brute 有 `escape_string` + CSRF；mtxMessage 被
> `htmlspecialchars` 编码。**能解释清楚为什么没报，比报一个漂亮的数字更重要。**

## 误报控制设计（本项目的技术重点）

| 漏洞类型 | 判定依据 | 防误报机制 |
|---|---|---|
| SQL 报错注入 | 数据库错误特征串 | 先比对基线，排除页面自然报错 |
| SQL 布尔盲注 | 恒真/恒假响应差异 | 相似度 >0.95 且差值 >0.05 才判定 |
| 反射 XSS | payload 未被编码地反射 | 先 canary 确认反射点，再判定上下文 |
| 命令注入 | 算术表达式的**计算结果**出现在响应 | 不认 payload 原文，避免回显页面假命中 |
| SSRF | 本机回调服务收到请求 | 每 payload 唯一 token，精确归因 |

设计原则：**判定依据必须是"漏洞行为本身的产物"，而不是"被回显的输入"。**
